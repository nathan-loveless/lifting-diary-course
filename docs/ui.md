# UI Coding Standards

These standards apply to all UI code throughout this project.

## Components: shadcn/ui ONLY

- **ONLY shadcn/ui components may be used for the UI in this project.**
- **ABSOLUTELY NO custom components should be created.** Do not write bespoke buttons, cards, inputs, modals, etc.
- Build every screen by composing existing shadcn/ui components (e.g. `Button`, `Card`, `Input`, `Dialog`, `Calendar`, `Select`).
- If a UI element is needed, find the matching shadcn/ui component and add it with the CLI:

  ```bash
  npx shadcn@latest add <component>
  ```

- Do not wrap, extend, or re-skin shadcn/ui components into new custom components. Use them as provided, customising only through their supported props, variants, and Tailwind `className`.
- Components generated by the shadcn CLI live in `src/components/ui/` and are the only components permitted.

## Date Formatting

All date formatting must be done with [date-fns](https://date-fns.org/). Do not use `toLocaleDateString`, `Intl.DateTimeFormat`, Moment, Day.js, or manual string building.

Dates are formatted as day with ordinal suffix, abbreviated month, and full year:

| Output        |
| ------------- |
| 1st Sep 2025  |
| 2nd Aug 2025  |
| 3rd Jan 2026  |
| 4th Jun 2024  |

Use the `do MMM yyyy` format string:

```ts
import { format } from "date-fns";

format(new Date(2025, 8, 1), "do MMM yyyy"); // "1st Sep 2025"
```
